# Grids

Jede Liste ist eine `GridPage` und wird bedient wie eine Liste in einer
Desktop-App: klicken, markieren, Rechtsklick, Tastatur.

```
[✕ 3 ausgewählt | Aktionen für diese Auswahl] ········ [Suche] [⋮]
[aktive Filter-Chips]
[das Grid — Kopfzeile bleibt stehen, Linien zwischen den Spalten]
[Anzahl ······························· Blättern]
```

## Spalten beschreiben, `useGrid` rechnet, `DataGrid` zeigt

Eine Tabelle beschreibt ihre **Spalten** und ihre **Aktionen** einmal. `useGrid`
hält den ganzen Zustand — Sortierung, Filter, Gruppen, aufgeklappte Zeilen,
Spaltenbreiten, Reihenfolge, Anheften, gespeicherte Ansichten, Bearbeiten,
Auswahl — und `DataGrid` zeigt ihn.

```tsx
const columns: GridColumn<Course>[] = [
    { id: 'title', header: t('courses.title'), hideable: false, width: 280, filter: { type: 'text' } },
    { id: 'category', header: t('courses.category'), groupable: true,
      filter: { type: 'choice', options: categories } },
    { id: 'price', header: t('courses.price'), align: 'right', aggregate: 'sum',
      cell: (c) => euro(c.price), filter: { type: 'number' },
      editable: { type: 'number', onCommit: (c, next) => savePrice(c.id, next) } },
    { id: 'starts', header: t('courses.starts'), filter: { type: 'date' } },
];

const grid = useGrid({
    id: 'admin.courses',               // fester Name — merkt sich die Einstellungen
    rows, getRowId: (c) => c.id, columns,
    mode: 'server',                    // Server sortiert und filtert (Inertia)
    onQueryChange: (q) => router.reload({ data: { sort: q.sorting, filter: q.filters } }),
    actions,
    isExpandable: (c) => c.offerings.length > 0,
});

<GridPage grid={grid} chips={<GridFilterChips … />} options={<GridOptions views={…} … />}>
    <DataGrid grid={grid} labels={…} renderDetail={(c) => <Offerings course={c} />}
        renderFilter={(col, close) => <GridFilterEditor … />} loading={loading} error={error} />
</GridPage>
```

**Client oder Server.** `mode: 'client'` (Standard) sortiert, filtert und
gruppiert im Browser — für kleine Listen. `mode: 'server'` lässt die Zeilen, wie
sie kommen, und meldet jede Änderung über `onQueryChange`; für die erste Anfrage
steht die gemerkte Sortierung in `grid.query`. Gruppieren gibt es nur im Browser.

## Was jede Spalte kann

- **Sortieren:** Klick auf die Überschrift — aufsteigend, absteigend, aus.
  **Umschalt-Klick** fügt eine weitere Sortierung hinzu (die Nummer zeigt die
  Reihenfolge). `aria-sort` sagt es Screenreadern. `sortable: false` schaltet ab.
  Text wird sortiert wie gelesen: „Lektion 2" vor „Lektion 10", Ä bei A; leere
  Werte immer ans Ende.
- **Spaltenmenü (⋮ an der Überschrift):** sortieren, **Filtern …**, danach
  gruppieren, links/rechts **anheften**, nach links/rechts verschieben, **Breite
  anpassen**, ausblenden. Alles auch per Tastatur.
- **Breite:** am rechten Rand ziehen — oder den Griff mit Tab erreichen und
  ← → (Umschalt: große Schritte), Pos1/Ende, Enter = an Inhalt anpassen.
  Doppelklick passt an.
- **Reihenfolge:** Überschrift ziehen und auf eine andere fallen lassen. Ein
  Klick ohne Bewegung sortiert weiterhin. Ohne Maus: „Nach links/rechts
  verschieben" im Menü.
- **Anheften:** eine angeheftete Spalte bleibt beim seitlichen Scrollen stehen
  (nach Auswahl- und Aufklapp-Spalte).
- **Filtern:** je nach Typ Text (enthält / ist genau / beginnt mit), Auswahl
  (Häkchen), Zahl (von–bis) oder Datum (ab–bis). Aktive Filter stehen als
  **Chips** über der Tabelle; ein Klick auf ✕ entfernt einen.
- **Bearbeiten:** `editable` macht eine Zelle zum Knopf. Klick → Feld, Enter
  speichert, Esc bricht ab. Der neue Wert steht sofort da; lehnt `onCommit` ab,
  kommt der alte zurück und der Grund steht am Feld. `validate` prüft vorher.
- **Kopieren und Export:** Strg/⌘+C kopiert die markierten Zeilen als Tabelle
  (für Excel). `grid.exportCsv()` liefert CSV der sichtbaren Spalten — alle Zeilen
  oder nur die Auswahl; mit `downloadText()` wird eine Datei daraus. Zellen, die
  eine Tabellenkalkulation als Formel ausführen würde, werden entschärft.

## Zeilen

- **Aufklappen:** `isExpandable` + `renderDetail` → ein ▸ vor der Zeile öffnet
  ein Detail darunter (z. B. die Ausführungen eines Kurses). Auch mit → und ←.
- **Gruppieren:** nach einer oder mehreren Spalten (`groupable`), verschachtelt.
  Jede Gruppe zeigt ihre Anzahl und die Summen (`aggregate`: count, sum, avg,
  min, max).
- **Lange Listen:** ab 200 Zeilen zeichnet das Grid nur, was sichtbar ist.
- **Laden, leer, Fehler:** `loading` zeigt Platzhalterzeilen und sagt „Lädt …"
  an; `error` zeigt den Grund und „Erneut versuchen"; ohne Zeilen erscheint
  `emptyState` oder `labels.empty`.

## Gespeicherte Ansichten

**Ansichten** (ganz oben im ⋮-Menü der Tabelle, `GridOptions` mit `views`) speichern Filter, Sortierung, Gruppen,
Spalten und Zeilenhöhe unter einem Namen, z. B. „Entwürfe dieser Woche". Die
aktive Ansicht kommt beim nächsten Besuch zurück — mit ihren Filtern. Weicht die
Tabelle ab, zeigt der ⋮-Knopf einen Punkt und der Eintrag „geändert"; „Ansicht aktualisieren" überschreibt sie.
Filter ohne Ansicht werden nicht gemerkt: ein Filter, an den sich niemand
erinnert, versteckt Zeilen.

## Aktionen wechseln mit der Auswahl

Jede Aktion sagt in `when`, wann sie gilt. Ohne `when` gilt `['none']`.

- **Nichts markiert** — `none`: Neu, Importieren, Alle exportieren, Neu laden
- **Eine Zeile** — `one`: Bearbeiten, Vorschau — alles, was _einen_ Eintrag öffnet
- **Mehrere Zeilen** — `many`: Auswahl exportieren, Zusammenführen
- **Eine oder mehrere** — `['one', 'many']`: Duplizieren, Verschieben, Löschen

Die Werkzeugleiste zeigt **nur Icon-Buttons**, jeder mit Tooltip samt Kürzel.
Die Hauptaktion (`tone: 'primary'`) ist gefüllt, bleibt aber ein Icon. Leere
Gruppen fallen samt Trennstrich weg.

## Auswahl

- **Klick** wählt eine Zeile. **⌘/Strg-Klick** nimmt eine dazu oder heraus.
  **Umschalt-Klick** wählt den Bereich bis zur zuletzt geklickten Zeile.
- **Kästchen** links, und oben „alle" (halb gefüllt, wenn nur manche gewählt
  sind). Klicks auf Knöpfe und Links in einer Zeile wählen nichts.
- **Doppelklick** führt die Standardaktion aus (`isDefault`, meist „Bearbeiten").
- Verschwindet eine Zeile (Filter, Suche, Seite), fällt sie aus der Auswahl —
  eine Aktion trifft nie eine Zeile, die man nicht sieht.

Die App legt fest, was geht (`selection`):

- `'multiple'` — Kästchen, Bereiche, alles auswählen.
- `'single'` — keine Kästchen, höchstens eine Zeile.
- `'none'` — reine Leseliste, nur die Listen-Aktionen.

In **⋮ → Zeilen auswählen** kann jede Person die Auswahl für diese Tabelle
abschalten; das merkt sich die Tabelle.

## Rechtsklick

Rechtsklick öffnet **dieselben Aktionen** als Menü, mit Kürzeln.

- Auf einer Zeile außerhalb der Auswahl: diese Zeile wird die Auswahl.
- Auf einer Zeile in der Auswahl: die Auswahl bleibt.
- Auf leerer Fläche: Auswahl weg, das Menü zeigt die Listen-Aktionen.

## Tastatur

Im Grid ist genau eine Zeile ein Tab-Stopp; von dort:

- **↑ ↓** — nächste Zeile, die Auswahl folgt (wie im Dateimanager)
- **Umschalt+↑ ↓** — Auswahl erweitern
- **⌘/Strg+↑ ↓** — nur den Fokus bewegen, Auswahl behalten
- **Leertaste** — Zeile an- oder abwählen
- **Pos1 / Ende** — erste / letzte Zeile
- **Enter** — Standardaktion
- **⌘/Strg+A** — alle auswählen
- **Esc** — Auswahl aufheben
- **/** — in die Suche springen
- **die Kürzel der Aktionen** — `shortcut: 'Mod+D'`; `Mod` ist ⌘ auf dem Mac,
  Strg sonst. Nur Aktionen, die zur Auswahl passen und nicht deaktiviert sind.

Beim Tippen in einem Eingabefeld greift keines davon. Kürzel wie `Mod+N`, `Mod+R`
oder `Mod+W` gehören dem Browser — nicht belegen.

## ⋮ Tabellenoptionen

Ganz rechts, neben der Suche: **Spalten ›** (ein Untermenü), Zeilenhöhe,
Zeilen auswählen, Zurücksetzen.

- **Die Grid-`id` ist ein fester Name, den die App wählt** — am besten der
  Routenname (`'admin.courses'`). Nicht die URL: Die ändert sich mit Filtern,
  Seitenzahl, Sprache und Umbenennungen, und jedes Mal wären die Einstellungen
  weg.
- **Gespeichert wird unter** `burgwiss-ui:grid:<id>`, mit einer
  Versionsnummer. Kaputte oder fremde Einträge werden ignoriert, nie halb
  gelesen. Wer wieder bei den Standardwerten landet, hinterlässt nichts.
- **Gespeichert werden _ausgeblendete_ Spalten.** Eine später neu eingebaute
  Spalte erscheint also für alle, statt still zu fehlen.
- Die Spalte, die eine Zeile benennt, bekommt `hideable: false`.
- Einstellungen gelten pro **Browser**, nicht pro Person. Wer zwei Personen an
  einem Rechner trennen will, nimmt die Nutzer-ID in die `id`.
- Ändert ein anderer Tab dieselbe Tabelle, zieht dieser Tab nach.
- Ohne `localStorage` (Privatmodus, voller Speicher) funktioniert alles weiter —
  nur eben für diesen Besuch.
